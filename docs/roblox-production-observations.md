# Improvements derived from production

These dated observations support the scoped decision record and specialized
modification/debugging workflow contracts. They distinguish saved evidence from
proposals and retain detailed input identities in ignored local study records.
Game-specific permissions and active release state remain with their owner.

## Follow-up from profile initialization — 2026-10-21

Game's next task saved a compact decision record before its implementation:
quoted decision origin with an explicit missing-session limitation, direct user
reaffirmation, actions allowed in the current leaf, deferred actions and actions
forbidden now. In that task, approval of saved data remained separate from
permission to activate the real store. The observed initialization also preserved
seven state files with verified backup hashes and identified its predecessor by
saved-place and input-receipt hashes.

The [task template](../templates/ROBLOX-TASK.template.md) now has a short optional
decision scope for tasks whose approvals differ across steps. This records the
existing instruction and target; it adds no grant or approval gate. Observers do
not inherit authority recorded for Game's implementation owner.

At this observation, only initialization and scope were demonstrated. The new
profile behavior, build and runtime were still pending. Later progression UI
leaves propose state/device layout captures; those are future opportunities for
the visual workbench, not new visual evidence. A useful next visual observation
would compare loading, ready, failure and reward states when actual UI captures
exist, keeping fixture state and physical-device acceptance explicit.

Dated input hashes and observed/proposed distinctions are retained in
`team/game-observation-progression-20261021.local.json`. Keep task-specific
permissions and changing profile details in that local record.


## Modification and debugging specializations — 2026-10-21

The [engine contracts](roblox-workflow-engines.md) connect existing task, parity,
review, runtime and visual tools to separate modification and diagnosis flows.
The [debug case](../templates/ROBLOX-DEBUG-CASE.template.md) retains source and
instrument identities, reproduction, controls, attribution and actual replay.

New profile-task development evidence retained an ambiguous installer anchor
that stopped before writes and a source-preservation detector that falsely
included a new global in an old function. Earlier guard fault detection and
visual capture exclusions provide independent examples of instrument defects.
The local study records their exact source/report hashes and result limits.
These cases justify the records and extraction proposals; they do not establish
that a unified engine runner has been implemented or that the active leaf has
completed saved-build/runtime acceptance.

# Learning workflow checkpoint

As of 2026-10-21 KST. This implements the requested production learning loop in
the existing Development Mapping, debug-case and task workflow.

## Delivered behavior

- Substantial handbacks, costly failures, corrected diagnoses and repeated work
  can yield a retained learning case. Routine work has no lesson quota.
- Development Mapping curates stable IDs, current qualified summaries, evidence,
  applicability, exclusions, disposition, destination/owner and reuse state.
- Task intake retrieves relevant IDs or records none. Delivery records actual
  application, adaptation, outcome, evidence and limits.
- Existing guidance, duplicates, project-only knowledge, deferral and rejection
  are valid destinations. Tools need stable supported mechanisms and controls;
  skill edits keep their existing arc-end/user-go boundary.
- Completed relevant instruction/behavior changes are handed to the bound Game
  integrator under the user's standing notification request. Receipts, actual
  acknowledgement and demonstrated adoption remain separate; current task and
  ownership boundaries stay intact.
- Raw game evidence and detailed local records stay local. Cases, proposed
  methods, implemented guidance, delivery and successful reuse remain distinct.

## Initial local pilot and verification boundary

The ignored `team/learning-index.local.json` indexes the retained response
freshness and same-state UI sampling cases. Their latest summaries qualify
historical evidence without rewriting the raw case chronology. Related later
observations are recorded separately; first prospective reuse was pending at
implementation. Later reuse status comes from the current local index and actual
task receipts, rather than this historical pilot summary.
Detailed input hashes, checks and review receipts remain in local task records.

The index is curated metadata. This change adds no production validator,
automatic semantic extractor, knowledge database, scheduler or skill writer.
The existing mapping and review tools remain available for relation views and
substantial candidate review. Neither a metadata check nor a mapped relationship
establishes actual reuse, game acceptance or new authority.

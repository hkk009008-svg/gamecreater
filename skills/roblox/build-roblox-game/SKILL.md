# Build a Roblox Game

Read the repository router and local binding, then the team's coordination state
and the bound game's `NOW.md`. Keep product decisions and live project paths in
those state files. This skill supplies no additional write, Studio, provider,
spend or publication authority.

Read [the Roblox team guide](../../../docs/roblox-team.md) for the working
protocol. Use its relevant sections rather than loading unrelated historical
engine procedures. Preserve existing shared skills when their actual method
applies; Unreal command lines and packaging gates do not establish Roblox
acceptance.

- For parallel work, assign exact writable paths and one integration owner with
  [the task template](../../../templates/ROBLOX-TASK.template.md). Existing
  release owners retain their files until an explicit handover.
- Before Studio mutations, identify the current instance and mode, assign one
  operator and respect the user's play/hold state. Inspect current tool schemas
  and retrieve the relevant Roblox tool skill when needed.
- Make changes durable in the project's stated source of truth. Test the
  resulting saved place through ordinary entry when claiming integration.
  Choose further multiplayer, visual, device and account checks according to
  the feature; keep their verdicts distinct.
- Deliver concrete behavior, evidence limits, cleanup and next action with
  [the handoff template](../../../templates/ROBLOX-HANDOFF.template.md). Prepare
  remaining publishing steps for the actual account owner. Verify changing
  Roblox requirements from current official documentation when executing them.
